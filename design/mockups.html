계산 규칙 앱이 만드는 숫자 — API 아님, 단말 계산

A. 거리 — 하버사인 누적

API 없이 단말에서 계산한다. GPS 점이 들어올 때마다 직전 유효 점과의 거리를 하버사인 공식으로 구해 더한다.

R = 6371000 m
dφ = φ2−φ1,  dλ = λ2−λ1   (라디안)
a = sin²(dφ/2) + cosφ1·cosφ2·sin²(dλ/2)
d = 2R · atan2(√a, √(1−a))
조건처리이유
acc > 30m 인 점누적에서 제외, 유효 점으로도 안 삼음오차가 걸은 거리보다 큼
d < 1m더하지 않음(직전 유효 점 유지)서 있을 때 GPS 떨림이 거리로 쌓이는 것 방지
규칙 B 점프더하지 않음, 유효 점도 갱신 안 함튄 점 한 번에 50m 가 생기면 안 됨
표시정수 m. 목표 거리 도달 시 햅틱 1회 + 숫자 강조자동 정지 아님 — 정지는 항상 사용자. 목표 100m 는 임시값, 논의 후 확정

샘플링 1Hz. 클립 단위가 100m 라면 도보 1.2~1.5 m/s 기준 약 70~90초, 점 70~90개. 클립당 JSON 은 수 KB. (100m 는 임시값)

B. GPS 점프 판정

연속 두 점 사이의 암시 속도로 판정한다. 사람은 3 m/s 이상으로 걷지 않는다.

v = d / dt            (직전 유효 점 기준)
jump = v > 3 m/s
    또는 d > 3 × max(acc1, acc2)   ← 오차 반경 3배 밖으로 튐
값어디에 쓰나
jump 플래그trajectory 점에 jump:true 로 기록은 한다(검수 웹이 볼 수 있게). 거리·궤적 선에서만 뺀다
클립 내 점프 횟수05 시트 경고 문구. 3회 이상이면 "GPS 점프 N회 — 반려될 수 있어요"
연속 점프 5회04 배너를 "GPS 신호가 튀고 있어요. 멈춰서 기다리세요" 로 바꿈

GPS 가 '이탈했다'는 건 결국 이 둘 중 하나다 — (1) 정확도가 나쁨(규칙 C), (2) 위치가 물리적으로 불가능하게 튐(점프). 검수자가 반려 사유 "GPS 이상"을 고를 때 근거가 되는 숫자를 앱이 먼저 만든다.

C. GPS 정확도 등급

accuracy표시동작
≤ 10m초록 점 "GPS 4m"정상
> 10m, 3초 이상노랑 점 + 상단 배너(행동 지시)녹화는 계속. 그 구간 초를 lowAccSeconds 로 센다. 정확도 때문에 녹화를 막지는 않는다
수신 자체가 없음회색 점 "GPS 없음"대기 화면에서 녹화 버튼 비활성(헛수고 방지). 녹화 중 끊기면 계속하되 05 에서 경고

lowAccSeconds 와 점프 횟수는 trajectory JSON 헤더에 같이 넣어 서버로 보낸다. 검수 웹이 "저정확도 30% 이상"을 걸러내는 근거.

F. 아직 정하지 않은 것

  • 클립 단위(100m)는 임시값. 논의 후 확정. 100m·20초 전제는 차량 시절 숫자라 도보면 70~90초 — trajectory 점 수·파일 크기·10초 백업 손실률도 그때 재계산
